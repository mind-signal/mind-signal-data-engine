# Band Power Analysis Contract (ANALYSIS-W001, 2026-07-31)

This governs `core/analyzer.py` and anything computing band power, Synchrony, or Friendship Score. It exists because several of these choices look like arbitrary implementation details but are actually pinned against real regressions — read it before "simplifying" the math.

## Computation method

- **Band power is PSD band summation.** `welch(nperseg=window_length, detrend=False)` produces the PSD; band bins are summed, multiplied by the bin spacing, and square-rooted.
- **Do not revert to a bandpass filter bank.** A causal filter bank was tried and failed: with a 128-sample window, the zero-initial-condition transient dominates the whole window, so band power came out proportional to a ~4200uV DC constant instead of the actual EEG (the "alpha pinned at 200" defect). Switching to a zero-phase filter didn't fix it either — recovery rate wobbled from 94.4% to 97.7% depending on starting phase, failing a phase-stability test.
- **It's a single segment, not an average.** `nperseg` equals the full window, so despite the "Welch" name this is really a single Hann-windowed periodogram. Per-window variance is high (measured coefficient of variation 0.31 on white noise). Session-level averages absorb this fine (hundreds of windows), but Synchrony — a window-by-window time-series correlation — is somewhat damped by this noise. Overlapping-window averaging was considered and rejected because it would further degrade the already-weak delta-band resolution.
- **Integration is a rectangular sum.** Do not switch to trapezoidal (`np.trapezoid`) — it halves the weight of band-boundary bins, which drops the delta 1Hz recovery rate from 91.3% to 70.7%. `test_delta_recovery_pins_rectangular_quadrature` pins this contract (a band-center tone gives the same result either way, so it can't be used to tell the two methods apart). The bin-spacing multiplication is pinned separately by `test_bin_width_scaling_holds_for_non_unit_resolution` using a 2-second window — a 1-second window has bin spacing exactly 1.0, so that test would pass even with the multiplication silently dropped.
- **The RMS conversion is an approximation.** Multiplying the summed PSD bins by bin spacing is, strictly, a Hann-squared-weighted average, not a plain mean-square. It holds for stationary signals and is exact for a band-center sinusoid, but diverges under strong trend (measured ratio 0.33 for a random walk, 1.18 for white noise). Treat it as a relative comparison metric, not an absolute calibrated value.
- **Expected RMS magnitude** is single-to-double digits under normal measurement. A 20uV alpha sinusoid in a 1-second window gives alpha = 14.14 (100% of the true value). Triple digits (e.g. alpha pinned at 200) indicate a DC offset or causal-filter transient defect. The absolute scale of live EEG is unverified pending real-hardware validation — the numbers above are synthetic-signal baselines.
- **Delta accuracy caveat** — recovery rate is 100% at 2Hz+ in a 1-second window but drops to 91.3% at 1Hz and 64.1% at 0.7Hz, due to 1Hz bin resolution; only a longer window fixes this. Components near the band floor are underestimated — be careful comparing across bands or interpreting similarity scores near delta.
- **Band boundaries overlap by design.** Boundaries are closed intervals, so the 4Hz, 8Hz, and 30Hz bins are counted in both adjacent bands. This is not an edge case — it happens on every continuous spectrum — so the sum of per-band values exceeds total power for broadband signal. It's a deliberate choice for center-frequency accuracy, applies identically to both subjects (no directional bias), and measured cosine-similarity impact is ~1e-4. Pinned by `test_band_edges_are_closed_intervals`.
- **Removed API** — `filter_delta` through `filter_gamma` (5 methods), `_butter_bandpass`, and `get_rms_power` were removed; the Welch path has no "filtered time series" intermediate product, so all had zero callers. Use `get_band_power(values, band)` instead.
- **Short windows are rejected, not silently wrong.** Below 128 samples, bin spacing widens enough that a band can miss every bin, silently returning 0.0 or nonsense (observed: theta and alpha both 11.86 at length 16). `_band_powers_from` raises `ValueError` at entry, so both `get_all_powers` and `get_band_power` are protected. The live path always hits exactly 128 because `streamer` empties its buffer non-overlapping.
- **There is exactly one DC remover.** `_remove_dc` is the only one, and `welch` is called with `detrend=False`. Stacking two DC-removal steps makes either one removable without changing the result, which silently defeats the regression test that pins this — a constant-DC-input test guards this contract.

## Synchrony

Correlation coefficient between two subjects' brainwaves. **Since 2026-08-03 (ANALYSIS-W004): Spearman rank correlation over the temporal-parietal (T7, T8, Pz) gamma channel average.** Pearson correlation over the alpha spatial average was the prior implementation and is reachable only via `FS_CORR_METHOD=pearson`. The method and target channels are defined in `server/services/score_params.py`'s `ScoreParams`; the actual value used for a given analysis is recorded in that analysis's `score_params` output.

**Caveat**: the canonical method is Spearman, and pipeline call sites reach it correctly because they pass `params.corr_method` explicitly. But `calculate_synchrony()`'s own default argument (`method: str = "pearson"`, `core/analyzer.py:55`) is still Pearson — it was not changed when the contract moved to Spearman. A direct call that omits `method` silently gets Pearson, not the canonical Spearman contract. Any new call site must pass `method` explicitly; don't rely on the default.

## Friendship Score

The canonical composite score (0..100). **Not** Synchrony times 100 — it's a min-max normalized weighted sum, so zero correlation lands at 50 points, not 0. The FAA avoidance term is still disconnected pending phase 2 wiring.
